# 反事实实验方案模板

以[执行与分析共同契约](../../docs/post_execution_analysis_contract.md)为字段、方法、测量和结果的共同依据。当前对话只提建议，不调用 frontmatter 工具；执行能力来自业务上下文和实际 `/api/v1/post/capabilities`。未取得能力时保留待映射草案。

1. 先核对数据版本、场景与 `metadata.sourceRecords` 执行前提。普通时间线接入成功不等于可运行。纪念塔仅使用已确认 A→M1、B→M2、C→M3 测试映射；源流量/FIFO重建和未校准性质写明，未测数值及校准分数保留 null。
2. 当前v2工作台统一设计实验池，不按观察/干预/机制分组。按用户目的选择变量与水平，逐组明确可检验假设、实验组名称、参照、主要终点和判定规则；方法为paired/ofat/ablation。三段分析从全部实验筛选，同一组可以复用。只有历史v1上下文才沿用分类型方法字段。请求尚未实现的交互、中介或微观作用链时保留缺口。
3. 每组明确参照、数值变化、控制条件、主要指标/单位、目标范围、预期方向与判断条件、重复依据和缺口。v2使用结构化primaryMetricId/expectedDirection/decisionRule等约定字段；v1仅使用已有hypothesis/change及说明文字，不超白名单。主要指标当前为全程全局值，区域/窗口PC特征不能替代尚未实现的区域/窗口主要终点。
4. 数值执行建议仅在 executionCapabilities 已给出时返回 execution 四个字段。核对文字与数值、参照组、动作实际生效时点，提醒零变化/重复配置；延迟超窗只用于明确的不生效对照。开放/引导是当前的出口分配和释放计划，不能描述成实体闸门或实时消息传播。
5. `designSchemaVersion=2` 时仅用assistant_message、可选groups和repeat_count；组字段遵守共同契约v2，禁止scheme_type。明确改变的控制量都须列入factorSymbols，参照可为统一池中的其他组，禁止循环。解释或检查只返回assistant_message。历史v1继续使用原白名单，不自动改写旧快照。
6. 共同种子按组配对，各指标报告实际有效配对数。重复1—50可用于工程检查；不足20对只作描述性估计，PC至少需要20个完整独立F-00样本，达到门槛也不等于统计充分。建议以试验方差和目标精度确定正式重复数，不能凭空保证显著性。
7. 用户先查看、修改并确认人工社会，再确认一份统一方案；修改共同条件或组配置后重新确认。人工社会文本修改须有真实执行映射才能运行。完整确认只保存reviewIntake和快照；运行页核对和保存执行矩阵后才显式启动。不得绕过版本、参照或隔离校验，不写成已运行结果。
