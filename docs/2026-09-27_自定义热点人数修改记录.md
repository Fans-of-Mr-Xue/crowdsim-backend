# 自定义热点人数：前后端修改记录

## 使用方式

重启后端，刷新前端页面。在仿真控制栏“本轮计划行人数”输入整数，点击“初始化 / 连接”，核对“后端确认”的实际人数，再点击“运行 / 继续”。

- 范围：0～10000 人；0 是空场对照。
- 留空：读取后端热点配置 visitor_count，当前纪念塔为 700 人；不再默认提交 8000。
- 修改已初始化的实验：先重置，输入下一轮人数，再初始化。重置保留输入；清空输入可以恢复场景默认值。
- 连接中、已连接、运行中及暂停时输入锁定，不能中途改变人数。
- 数量表示整轮热点访客总数，不是同时在场人数，也不是渲染抽样上限。

## 后端

- `crowdsim/scenarios/generated_hotspot_demand.py` 新增 `HotspotDemandSpec`，从配置选择热点，以现有生成器重新生成指定数量访客。校验整数和上下限，始终传入 background_count=0。
- `crowdsim_overlay_server.py` 将内置 hotspot 预设由 fixed 改为 generated_hotspot；research/custom/fixed 保留原模式。
- `SimulationRuntime.initialize` 在本轮目录生成需求，再执行现有画像与速度初始化；不通过复制旧行人放大人数。替换 SUMO 原路线文件，避免旧 700 人叠加；空场也覆盖原需求。
- 初始化回执包含请求值、实际值、默认值、限制和人数账本。相同人数再次 configure 不重建；不同人数需要重置。运行或暂停中不动态扩缩容。
- 生成式热点新建/重建时省略人数使用配置默认值。普通模式保留原有语义。
- 较耗时的生成/初始化放入工作线程，消息处理仍串行等待，不与仿真循环并发操作。新增 preparing 提示，并等待初始化完成后才允许 start。取消时等待工作线程完成，再清理资源。
- generated_hotspot 禁止额外 route-files 覆盖，避免请求人数和实际需求不一致；回放依然使用原有普通运行模式。

本轮保存：

- `hotspot.config.json`：生成配置快照（visitor_count 保留默认值，实际覆盖值在报告中）。
- `hotspot.generated.rou.xml`：本轮重新生成的原始需求。
- `demand.rou.xml`：SUMO 使用/回放用需求，非零人数附加现有画像速度类型。
- `demand_generation.json`：实际人数、随机种子、模板与配置哈希、刷新边、观赏区及出入口等分配统计。
- `manifest.json`：人数设置和生成报告摘要字段、最终需求哈希。

公共路网、配置、原预生成路线、既有 runs 均不被覆盖。

## 前端

- `CrowdSimSimulationImmersive.vue` 输入支持留空和 0；提交前校验；显示后端确认人数与默认值，以及待刷新、已刷新、当前在场、已完成离场人数。
- 初始化等待上限改为 120 秒，展示准备提示；重置/断开清除旧回执，保留用户输入。
- `crowdDemandConfig.js` 集中管理人数请求和人口账本展示口径。
- `crowdSimConnection.js` 只接受当前握手 request_id 的 preparing；它不会提前解锁运行。

## 不变项及边界

不改变现有刷新位置、三段到达比例、600～800 秒活动时间、活动结束后 0～90 秒的离场延迟、观赏弧段权重、寻路、画像速度、jamtime、五状态判定和渲染上限。相同人数和种子生成可复现的需求；不同人数会按现有分配规则重新采样，不保证每个同名行人的位置保持一致。

大人数会提高单位时间刷新量和拥堵压力；10000 是允许输入的上限，不是实时性能保证。1800 秒时间轴不随人数自动延长，拥堵严重时可能仍有行人未完成行程。

## 验证

- 新增人数输入/账本测试与连接测试；连同既有五状态测试共 16 项通过，Vue 组件编译通过。
- 前端生产构建通过；仍有项目原有的大包及动态/静态混合导入警告。
- 生成器验证 0、1、12、默认 700、1000 人：人数精确、ID 唯一、背景为零、原预设文件不变、同种子可重复；单独验证 10000 人生成成功（本机约 1.85 秒，仅生成需求，不代表完整仿真耗时）。
- 使用现有 sumo Conda 环境进行临时真实 SUMO 测试：非法输入拒绝、0→12 重置、相同人数不重建、不同人数须重置、恢复默认 700、manifest 人数一致；真实 WebSocket 的 preparing/init 和初始化期间 ping/pong 测试通过。
- 后端共 38 项测试通过：新增人数相关 3 项、场景选择 5 项、既有热点生成 4 项，以及 WebSocket / 仿真循环 / 人口守恒 26 项。
- 测试输出位于临时目录，不向正式 runs 写测试记录；未重新安装依赖。未进行 10000 人完整运行或真实浏览器人工联调。
