# 事后反事实实验：SUMO 与后端对接清单

日期：2026-10-30。当前基线见 [执行与分析共同契约](post_execution_analysis_contract.md)。本文是待办及验收要求，不表示功能已经实现。初版仅统一skills、Agent和文档；当前工作台更新另已接入统一实验池的保存校验、执行模板与分析筛选，未修改SUMO控制、测量及MongoDB仓储实现。

多数工作位于 Python 需求编译、TraCI 控制、测量和归档适配层；目前没有证据要求修改 SUMO C++ 内核。以下“建议产物/字段”需双方确认后实现，并更新能力声明和版本。

## 一、请 SUMO 同事核对或实现

### S0 / 新流程对接：人工社会配置的真实执行映射

- 新工作台先查看、修改并确认人工社会，再统一设计变量—假设—实验组。配置随 `reviewSnapshot.artificialSociety` 保存，文本修改位于 `overrides.agents/environment/rules`。当前非空修改会由 `schemas/unified_design.py::validate_unified_execution` 拦截，错误码 `SOCIETY_MAPPING_REQUIRED`；不会把修改当备注后仍按旧模型运行。
- 请与前端/后端共同定义可执行的主体、环境和规则字段、单位、范围及版本；将用户确认的结构化配置编译进实际人员、路网或控制/测量参数，保留编译摘要与配置指纹。不能直接执行自然语言文本。
- 验收：同一配置指纹用于全部组；更换配置后旧方案确认失效；运行归档能读回真实参数和版本；不支持的字段明确拒绝。现有空修改仍沿用已绑定模型，可以正常执行。此项可能涉及需求编译/TraCI适配，当前不要求修改SUMO C++内核。

### S1 / P0：模型与测量有效性诊断

- 位置：`postanalysis_api/workers/memorial_scenario.py`、`controlled_sumo.py`、`measurement.py`。
- 问题：已有完整时窗验收中所有组峰值密度相同、全到达指标均右删失；工程基线未拟合校准。需定位入流/FIFO驻留、主动置零速率、路径容量、局部裁剪面积及测量范围对结果的影响。
- 请交付：按时间/区域的人数收支、主动停留人数与时长、计划及实际进入/到达人数、未离场原因；关键峰值的网格ID、人数、有效面积和时刻；参考人数与实际测量范围的对应说明。校准允许偏差应依据数据来源共同确认，不硬填80分。
- 验收：每个异常能追到具体人员/网格/控制事件；比较干预前的同种子人员与状态；说明校准与留出核验的使用方式。有效性检查不要求策略必然改善。

### S2 / P0：明确开放、引导及延迟的实际作用

- 位置：`memorial_scenario.py::compile_routes/control_schedule`、`controlled_sumo.py::execute`。
- 当前：编译时按释放时刻和随机数分配出口；开放时刻只约束 C 出口人员释放，不是实体闸门开闭；没有消息传播和运行时接收/认知模型。
- 请确认研究对象是“预定路径/释放策略”还是“运行时引导与真实通行控制”。前者可沿用当前实现并准确命名；后者需在 TraCI 层实现带时点的通行控制、引导接收、延迟生效和实际改道。不要为满足文案虚构新机制。
- 验收：动作前无非预期处理差异；动作发生及生效时刻可查；延迟超出窗口明确不生效；遵从0/1边界与中间比例可核对，分配与实际执行分开。若研究交互效应，还需允许相应组合设计，不能只改方法名称。

### S3 / P0（需要机制路径结论时）：补齐实际事件证据

- 当前只有真实 hold/release 等事件，以及编译出口分配计数。
- 建议事件最小信息：`runId/personId/timeSeconds/type/actionId/regionId`；有真实改道时再记录 `fromEdgeId/toEdgeId/reason`，有接收/遵从机制时再记录触发、接收、选择、生效及对应状态。不存在的过程不产生日志。
- 请交付：能区分“分配出口”“实际通过出口”“完成最后行走”的记录；对每条宣称的机制链给出可关联的控制、个体状态和流量证据。
- 验收：同种子完整/消融组只有预定模块不同；涉及人员ID、需求、停留随机数和其他控制保持一致；作用时点和下游变化可追溯。模块差值本身不自动升级为中介效应。

### S4 / P1：支持主要终点的窗口、区域和人群

- 位置：`measurement.py`、`sumo_batch.py` 的特征提取；后端共同修改请求与结果 schema。
- 当前七项主要指标是全程全局值，PC特征的区域密度/压力取相交网格极值，速度按入口edge人员；缺少统一空间裁剪口径。
- 请交付：预先指定区域、左闭右开时间窗和目标人员集合的指标；统一人员归属与有效面积，保存几何/网格口径。区分自然停留、控制停留和拥堵。
- 验收：全局/区域、干预前/后、人员—时间权重与帧均值均有可人工复算样例；PC特征和主要终点不因同名指标混用公式。

### S5 / P1：到达、删失与安全区口径

- 位置：`sumo_batch.py` 的 tripinfo 读取及源 cohort 生成。
- 当前 `evacuation_time` 是从20:00起的最后到达秒数，全体未完成即null；尚不等于从干预开始计的安全区疏散耗时。
- 请交付：事先明确目标人员集合、安全区/出口、计时起点、观察截止时刻；逐人离开/到达时间和未完成状态；固定时点完成比例、剩余人数等可用终点。
- 验收：全体/部分/无人到达、晚进入者、窗口内未生效动作均可解释；保持null和删失原因。生存/中介等统计算法由分析端另行实现。

### S6 / P1：采样和极值的测量敏感性

- 位置：SUMO 输出参数、`measurement.py` 和指标版本。
- 请核对：5秒采样能否覆盖拟研究的短时风险；裁剪面积很小的网格是否主导峰值；采样起止边界与累计人时是否一致。
- 验收：按研究需要选择少量网格/采样配置比较，报告指标变化和开销；保留原数据，不把改变后的口径与旧版本直接合并。此项不预设必须修改采样频率。

### S7 / P1：输出可复现材料

- 位置：`sumo_batch.py`、`memorial_scenario.py`，配合归档接口。
- 请交付：SUMO实际版本、代码提交/发布标识、路网/投影、完整输入与配置、需求与SUMO随机数设置、指标与采样版本、运行命令；FCD/tripinfo/日志的字节数、SHA-256及可持久保存的文件引用。
- 验收：离开原机器目录后仍可取回、校验并重跑；旧轨迹按旧投影解释；所有材料绑定同一 runId 和版本。输入与输出由后端归档，避免只记录绝对路径。
