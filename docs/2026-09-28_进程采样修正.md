# 进程资源采样：中文环境解析与完整性修正

## 范围

只修改系统资源采样器及测试，不改前端、SUMO 行为或仿真速度。
不提供旧日志转换、兼容或补录；不提前启动采样以记录未连接的演示页面。
仍在运行初始化成功后启动，每约 5 秒后台采样，运行关闭时清理线程。
重启后端后生效，继续写入各轮的 performance.system.jsonl。

## 原因及修复

ps 的 lstart 在中文环境只有四段日期，原解析器假定五段，导致短进程名整行遗漏、长进程名错位。
现在仅给 ps 子进程设置 LC_ALL=C、LANG=C，并加 -ww，既固定日期格式又避免终端宽度截断。
不会修改 os.environ、系统语言、SUMO 环境，也没有安装依赖或新增管理员采样。
解析器校验日期结构、PID/PPID、CPU 累计时间和非负 RSS；坏行计数，不再静默当作成功。

## 新的质量字段

host.processes.status 为 ok、partial 或 unavailable：

- quality.raw_rows / parsed_rows / failed_rows：非空原始行数、成功行数、失败行数。
- quality.backend_pid_found：后端进程必须出现，否则整个进程快照为 unavailable，CPU 基线清空。
- quality.missing_groups：当前未匹配到的分组；缺少可选组本身不代表失败。
- reason：空快照/自身 PID 缺失或部分解析失败的原因。

每个分组固定存在，包含以下字段：

- status：快照可用性；无匹配进程为 not_found，不能解释为 CPU 零占用。
- cpu_status：ok、warming_up、partial、not_found、unavailable。
- process_count / cpu_measured_process_count：当前匹配数量及可计算 CPU 差分的数量。
- previous_processes_not_observed：上一样本进程本次消失或 PID 被复用的数量，不武断区分退出与漏采。
- cpu_one_core_percent：仅完整快照、所有当前进程差分有效且无上一样本进程消失时给出，否则 null。
- observed_cpu_one_core_percent：已成功差分的进程之和；部分数据不可冒充全组总量，无有效值为 null。
- rss_bytes_sum：完整快照的匹配进程 RSS 合计；不可用/部分快照/无匹配为 null。
- observed_rss_bytes_sum：实际解析到的匹配进程 RSS，部分数据只作参考。

进程行增加 cpu_status。首次采样、新进程出现需要建立基线；PID 复用或计数回退分别标记
pid_reused/counter_reset，不计算错误 CPU。命令超时或读取失败清空 CPU 基线，下次重新建立。
真实零占用保持数值 0，100% 代表一个 CPU 核，允许超过 100%。
进程在两次采样之间创建并退出仍可能完全不可见；完整性状态不是操作系统级无损进程审计保证。
浏览器组仍包含所有浏览器/WebKit 相关进程，不能精确归因于当前页面。
RSS 合计可能重复包含共享页；整机 CPU、GPU、热状态等其他接口未改动。

## 验证

采样模块 16 项测试通过，覆盖中文父环境、子进程环境隔离、空格名称、异常格式、长 CPU 时间、
缺少自身 PID、坏行、首次/零占用、新增/消失/PID 复用、计数回退、命令失败及线程生命周期。
另运行既有性能/倍率/WebSocket/仿真循环/关闭流程回归测试。

实机从 zh_CN.UTF-8 环境启动临时小型 SUMO 场景：一个完整样本 500 行全部解析成功，
后端、SUMO、浏览器、WindowServer、编辑器分组全部出现；后端父环境保持中文。
三次采样耗时约 57/65/84 ms（短时功能测试，不代表大型任务固定开销）。
关闭后采样线程退出，临时日志随测试目录回收，没有运行正式纪念塔任务。
