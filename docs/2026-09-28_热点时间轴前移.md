# 热点时间轴前移

## 目的

取消纪念塔场景启动后、首位行人出现前的空场等待，不改变人数、路线、观赏位置、刷新间隔、到达高峰形状或活动持续时间。

## 实现

- 在 `config/crowd_hotspots.json` 的纪念塔配置中启用 `align_first_visitor_to_zero`。
- 完成原始需求生成和随机抽样后，取最早计划刷新时间作为前移量；将所有行人的刷新、计划到达、绝对离场时间，以及活动和到达分段时间一起前移。
- 按未舍入的计划计算，再输出两位小数的 SUMO 时间，避免从已舍入 XML 反算导致误差。路线、位置、相对停留时长和离场延迟长度不变，不增加运行期逐帧计算。
- `PopulationManager` 从新生成的 XML 读取前移后的绝对离场参数；初始化时以生成报告更新本轮 `HotspotCatalog`，保证发给前端的活动时间与后端一致。重复应用报告不会重复扣减。
- 服务生成记录的 `generation_version` 更新为 2。前端无需修改。

## 日志和复现

每轮 `demand_generation.json` 和 manifest 中的 `demand_generation` 保存：

- `timeline_shift_seconds`：本轮实际前移量。
- `timeline_alignment_status`：对齐结果。
- `unshifted_planned_departure_window_seconds`：前移前的刷新范围。
- `configured_*`：原配置时间信息；`hotspot.config.json` 仍保留原始输入配置。
- `planned_*`、`activity_window_seconds`、`visitor_arrival_profile`、`visitor_release_window_seconds`：实际生效的本轮时间信息。

默认 700 人、种子 20260908 的结果：

| 项目 | 前移前 | 前移后 |
| --- | --- | --- |
| 刷新范围 | 46.7645～525.2524 秒 | 0～478.4878 秒 |
| 计划到达范围 | 240～660 秒 | 193.2355～613.2355 秒 |
| 活动时间 | 600～800 秒 | 553.2355～753.2355 秒 |
| 离场释放范围 | 800～890 秒 | 753.2355～843.2355 秒 |

不修改历史 runs 或静态预生成路线文件。新服务任务会重新生成需求；历史任务保持原样。使用静态路线文件的独立实验需重新生成路线才会应用此功能。

## 边界保护

- 开关默认关闭，仅当前纪念塔配置启用；0 人任务不移动时间轴，原本从 0 秒刷新的任务不再移动。
- 若配置未来重新加入背景行人，本功能不移动时间轴，以免改变已有背景交通。
- 若未来配置了早于首位刷新的活动/时间窗口，前移量受该更早时间限制，避免负时间；报告标记 `limited_by_earlier_time`。当前纪念塔配置不触发该限制。
- 保留固定仿真时间上限，不改变仿真倍速、步长或自然结束机制。

## 验证

共 32 项测试通过，包括不同人数和种子的前移前后对比、0/1/12/700/1000 人需求生成、人数与路线/位置不变、时间间隔不变、重复应用与配置隔离、真实 SUMO 启动/重置和前 2 秒内已有行人、停留离场及倍速回归。未运行完整 700 人仿真。

使用现有 `sumo` conda 环境，无依赖安装。重启后端并新建或重置任务后生效；首位行人在 SUMO 首个有效步和前端更新后可见，并非保证点击的同一瞬间显示。
