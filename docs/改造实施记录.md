## 阶段 4：路线候选与计划执行

状态：通过。

- 新增 `route_provider.py`：只接受已加载网络中的可步行边，候选使用 SUMO 行人路线接口。
- 新增 `plan_executor.py`：统一执行 continue、slow_down、wait、reroute、change_goal；follow_group/seek_help 必须先归约，任意道路 ID 被拒绝。
- 速度约束按 base、strategy、hazard 取最小值；等待到期重新计算，不盲目恢复固定速度。
- 真实动作测试：wait 5 s 漂移不超过 0.01 m并恢复；reroute 实际 walking stage 改变，ID/位置连续；2 passed。

失败与修正：

1. 首次把 pedestrian-only 网络的连通性按车辆 `<connection>` 检查，合法路线被拒绝。改为校验步行边节点拓扑。
2. 首次替换 walking stage 使用无效默认 arrivalPos，TraCI 明确拒绝。改为继承当前 stage 的 arrivalPos 后通过。

## 阶段 5：画像、信息、同步状态与同行关系

状态：通过。

- `population_profiles.py` 使用固定种子和 person ID 稳定抽样；14 个有效属性全部在 `config/attribute_registry.json` 登记消费者、范围、来源状态和测试编号。
- `crowd_environment.py` 只从同一 SUMO 快照和个人感知半径构造邻居、有效面积、客观密度、主观拥挤与可见危险，不泄露全局实时态势。
- `state_updater.py` 批量同步更新压力、疲劳、受阻持续时间和恢复过程；遍历顺序不改变结果。
- `information_model.py` 实现范围、延迟、有效期、去重、消息来源信任和权威指引倾向。
- `group_manager.py` 只接受需求账本中的真实 person ID；支持出发前登记、同行成员、领队和已配置会合 POI，不复制不可见同伴坐标。
- `activity_planner.py` 将 `visit_purpose` 与 `familiarity` 用于初始化有限已知 POI；职业、国籍、母语仍只用于展示，未恢复旧文化参数表。

失败与修正：同行组允许在成员出发前登记时，早期实现尝试直接访问尚不存在的 `AgentState`。修正为只给已经出发并建立状态的成员绑定关系，后续边界自动补齐。

## 阶段 6：决策、事件、危险与边界命令

状态：通过（LLM 仅预留接入点）。

- `agent_decision.py` 的规则和未来 LLM 共用 `BehaviorPlan`、有限路线候选和同一执行器；提示上下文只包含个人可知信息。
- `llm_gateway.py` 定义厂商无关 `LlmGateway` 协议。由于尚未收到具体模型接入方法，不绑定 HTTP/SDK；未注入 gateway 时明确使用规则路径。
- `decision_scheduler.py` 对所有到期人员进行公平轮转，具有模型预算、并发上限、失败回退和旧快照拒绝。
- `event_catalog.py`、`event_manager.py`、`hazard_model.py` 将一般突发事件拆为信息影响与显式物理速度约束；事件从不直接乘人数或客观密度。
- `runtime_commands.py` 将事件、危险、干预和同行关系命令排队，在 tick 边界统一校验、生效和记录。暂停时在当前冻结边界处理。

## 阶段 7：自主活动、实验记录与回放

状态：通过。

- `route_provider.py` 使用 SUMO 行人路由生成当前目标、活动 POI 和后续出口候选；`plan_executor.py` 预置 walking → waiting → walking 阶段，活动到达不删除 person。
- 位于 internal junction edge 时禁止替换路线，延后至普通边；不可达的“当前边—目标”组合负缓存，避免每步重复查询。
- `experiment_recorder.py` 保存 manifest、实际需求哈希、画像、决策上下文/候选/执行结果、命令、消息、生命周期、轨迹、指标、SUMO 日志和最终摘要。
- `scripts/run_experiment.py --until-finished` 支持运行到 SUMO 自然结束并有最大步数保护。完整实验 `run-5bf7ba94f44f4f74a3eaad318ee3426b` 运行 273 步/136.5 s：40 人全部出发、40 人全部到达、未知消失 0、守恒误差 0。
- `scripts/replay_experiment.py` 只重放已记录计划，不调用模型。上述完整实验共 7125 条轨迹、1798 次决策，位置与速度最大误差均为 0，回放同样为 40 人全部正常到达。

失败与修正：

1. 回放最初同时由调用方和 runtime 传入两次 `--route-files`，SUMO 拒绝启动。runtime 现在检测完整外部覆盖，不再重复追加；回放恢复为零差异。
2. POI 候选最初在 internal edge 上使用普通 lanePosition 查询，SUMO 报无效出发位置。改为按方案延迟到安全普通边。
3. 长时域试跑发现不可达演示出口会被逐步重复查询。新增成功/失败候选缓存，并在 diagnostics 中报告不可达组合数。
4. 首版回放把最后一条在场轨迹时间当作结束时刻，少执行了最终到达边界。改为同时读取记录摘要的最终时间；完整回放人口账本恢复为 40/40。
