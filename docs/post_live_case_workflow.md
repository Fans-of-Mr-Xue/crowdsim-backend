## 页面入口与数据流

在“事后：复盘解释 → 需求界定”顶部选择：

- **载入预设并编辑**：检查 MongoDB 和 SUMO，上传完整规范数据及原文件到 MongoDB/GridFS，保存预设方案，打开原工作台。可以编辑假设、参照、启动时点、遵从比例、延迟、主要终点、方向及重复次数。修改后重新确认方案。
- **一键运行完整案例**：使用同一预设，依次上传、保存方案、读取执行模板、创建批次、启动 SUMO，然后进入运行平台。无需填写内容或调用大模型。

运行平台保留实时进度、轨迹重演、取消、任务记录和分析流程入口。完成后按“观察分析 → 干预分析 → 机制分析 → 复盘报告”浏览当前批次数据库结果，或下载分析 JSON。导航保留 conversationId/batchId。

原“案例演示”现在明确标为**静态讲解**，仍是旧的隔离式预录展示。完整运行使用上述真实案例入口，不带 demoCase 参数，不读取预设结果。

预设为完整19800秒的合成参考案例，F-00加5个反事实组，每组3个共同种子，共18次运行。预设的是输入和待验证假设，输出只能来自实际 SUMO。基线尚未拟合校准；A/B/C到M1/M2/M3为工程映射，M3不是真实北侧通道。

## 因果协议与指标

估计目标为测试模型内的 E[Y(do(candidate), U) − Y(do(reference), U)]。独立实验单位是一次随机种子运行，同一种子跨世界线配对；固定源流量、路网、初始化及模型版本。使用配对均值差和2000次配对 Bootstrap，逐对照报告95%区间。

| 对照 | 方法与待检验问题 |
| --- | --- |
| OBS-01 vs F-00 | 完整提前开放与引导策略是否降低风险暴露 |
| INT-01 vs OBS-01 | 相同参数的零差异对照，逐种子核对可测指标是否一致 |
| INT-02/03 vs OBS-01 | OFAT仅延后启动时点，检验暴露是否增加 |
| MEC-01 vs OBS-01 | 仅将遵从比例从0.7消融至0，检验引导模块贡献 |

主要终点为高密度风险暴露人时（人·秒）。次要终点为网格峰值密度、人时加权平均速度、密度乘速度向量方差的压力代理峰值、暴露去重人数、拥堵网格累计时长、全部到达时间。定义、单位及输入需求由 `schemas/metrics.py` 版本化，随结果返回并在页面展开查看。压力代理不是接触力；未全部到达时到达时间保持 null。

至少20个有效配对时，才按预登记主要终点方向与逐对照区间标记支持、相反或证据不足；少于20对仅作描述性比较。20是本项目最低展示门槛，不是功效保证。区间未作跨对照多重比较校正，不能声称总体显著。自定义判定规则原文保留，自动状态仅按页面说明的主要终点标准解释。

结构发现复用 `algorithms.pc.pc_discovery`：PC-Stable、Fisher-Z及Meek R1–R3。仅使用独立F-00种子，一次运行每个特征产生一个窗口汇总值。样本不足、常数/奇异特征、重复种子、定向冲突均显式记录；未识别方向保持无向。相关算法说明见[causal-learn PC官方文档](https://causal-learn.readthedocs.io/en/latest/search_methods_index/Constraint-based%20causal%20discovery%20methods/PC.html)。机制消融估计预定义模块贡献，不等同于自然间接效应或历史事故因果事实。

## 连接与失败边界

事后接口仍挂载在现有8765端口的 `/api/v1/post`，复用原MongoDB环境配置。新增 `GET /health` 分别检查真实MongoDB ping与SUMO能力，不返回地址、用户名或凭据。依赖不可用时，在上传前停止并给出连接提示；没有本地存储或演示数据降级。

原文件以UTF-8原始字节Base64传输并存入GridFS。普通文件的FileReader data URL直接保留；内置JSON文本显式编码，避免把JSON原文当作Base64。

方案与数据版本锁定、用户/工作区隔离、执行参数限制及幂等写入沿用现有接口。切换对话后丢弃迟到响应，停止后续创建和启动；已经被后端接受的运行继续由运行平台管理。预设每次在新事后对话中创建，不覆盖原对话。

## 参考因果图数据库设计建议

以下为建议设计，本轮未创建集合或自动接入参考图。建议新增 `postanalysis_reference_graphs`，保存每个已发布图版本，按现有owner/workspace隔离：

| 字段 | 内容 |
| --- | --- |
| graphId / version / contentHash | 稳定编号、版本及内容哈希；更新产生新版本 |
| scenarioId / modelId / modelVersion / geometryVersion / ruleVersion | 与本次执行匹配的场景和模型配置 |
| variableSchemaHash / nodes | 每个节点的指标、区域、时间窗、聚合方式、单位和时滞定义 |
| edges / graphType | 边及方向语义；DAG、CPDAG等图类型 |
| referenceKind | known_scm、validated_simulator或expert_reference |
| provenance / evidence / status | 生成机制、来源证据及发布状态 |

创建实验时匹配并锁定参考图，将referenceGraphId、version、contentHash和节点映射存入实验快照。评分时读取锁定版本，或使用归档的内容快照；历史批次复用自己的版本。提取图与验证参考图分别保存，验证参考图保持独立来源。

节点必须与PC实际使用的窗口汇总变量一致。微观规则图转换为这些宏观变量的参考图时，应记录转换方法和验证证据。已知SCM真值和专家参考图分别标记，后者用于报告与专家知识的一致性。结构评价建议分别计算骨架和方向Precision/Recall/F1、SHD，并处理CPDAG的未定向边；结果中同时记录图版本、节点映射、样本量和计分口径。
