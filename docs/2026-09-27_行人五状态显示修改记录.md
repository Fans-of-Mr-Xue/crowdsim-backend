# 行人五状态显示修改记录

## 判定规则

本次实现的是可配置的工程风险提示，不是伤害概率模型。颜色优先级：红 → 橙 → 蓝 → 黄 → 绿。

| 状态 | 颜色 | 条件（由上至下判定） |
| --- | --- | --- |
| high_risk | 红 | 密度 ≥ 4.0 人/㎡持续5仿真秒；或者密度 ≥ 3.5 人/㎡且速度 < 0.2 m/s，两条件同时持续5仿真秒 |
| crowded | 橙 | 密度 ≥ 1.5 人/㎡，未触发红色 |
| planned_stop | 蓝 | hotspot_dwelling 或尚未到期的 planned_wait_until，未触发红/橙 |
| busy | 黄 | 密度 ≥ 0.5 人/㎡，或非计划低速持续5仿真秒，未触发前述条件 |
| normal | 绿 | 其他 |

低速不等于零速，严格使用 < 0.2；密度阈值均含等号。持续条件中断立即清零，条件恢复后重新累计。退出红色不另加滞后时间。计划停留者也会累计高密度及密集低速证据，但不被算作行为决策中的被迫堵塞。

特别修正：不能用“当前密度 ≥ 3.5 + 过去任意地点低速5秒”触发红色。新增 dense_low_speed_duration 专门计算两个条件同时成立的时间。

## 后端

- 新增 config/crowd_visual_state.json，运行时真实加载；阈值校验为有限正数且密度阈值递增。
- 新增 domain/crowd_visual_state.py：纯分类与显示计时；采用独立 visual_blocked_duration，不改变原来 blocked_duration 对寻路、画像及行为决策的影响。
- AgentState 新增 low_speed_duration、critical_density_duration、dense_low_speed_duration、visual_blocked_duration，StateUpdater 每仿真步更新一次。
- SimulationRuntime 每步缓存统一判定结果，FrameSerializer、计数、轨迹记录复用相同结果。暂停或重复请求帧不会推进计时，3倍播放不改变仿真秒阈值。
- 保留行人 color 和旧 congestion；新增 visual_state、visual_reason、density_person_per_m2、density_valid，以及相应的 *_duration_seconds 证据字段。
- init 提供 crowd_visual_state 元数据；metrics 提供 visual_state_counts、visual_density_unknown_count。原 density_levels 仍描述瞬时密度等级，与经过持续时间确认的 visual_state 分开。
- trajectory.csv 追加密度、五状态、原因、活动状态及计时列；metrics.csv 追加五状态人数与密度未知人数。manifest.json 保存规则版本、实际阈值、密度算法及参数属性。
- 车辆继续原有颜色规则。

当前保留既有密度算法（同 edge、个人感知半径、2r×人行道总宽度近似面积）。固定尺度、跨 edge 的客观密度重构留待后续；该限制已经记入 manifest。缺少密度时清除高密度计时、输出 density_valid=false 和密度未知人数，不把未知密度冒充为0。

## 前端

- crowdVisualState.js 集中定义状态/配色、兼容解析、归一化和人数读取。
- normalizeGeoEntity 保留后端活动状态、密度与原因等字段。
- 新协议行人优先使用 visual_state；前端事件/积水装饰逻辑不再覆盖其颜色或速度。车辆及旧协议保留原有逻辑，并兼容黄色。
- CrowdSim3DViz 用数据表生成样式索引，新增黄色；插值时显示颜色和状态说明一起切换。
- CrowdStateLegend 共用图例：后端五状态及实时人数、旧版说明、未接管时演示人群类型。沉浸页面增加浮动图例，避免原控制栏隐藏时看不到。
- 统计采用完整后端人数，不以最多10000个渲染样本或局部视角的装饰复制点计数。
- Canvas 发光绘制自动读取新样式；保持既有15 FPS及人数上限。

## 验证与使用

- 前端：node --test tests/crowdVisualState.test.mjs；Vue组件编译与图例服务端渲染；npm run build。
- 后端：sumo conda 环境，tests.test_crowd_visual_state、tests.test_state_updater、tests.test_crowd_environment。
- 独立 SUMO 走廊场景验证帧、状态计数、轨迹、manifest、重置及重复序列化。测试写入临时目录，不运行纪念塔完整任务，不写入项目 runs。
- 后端修改后需重启服务；前端刷新页面后发起新任务。既有 runs 不迁移、不重写。
