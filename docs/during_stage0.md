## 核心区域和状态口径

核心区域固定为 `679361567#1`、`679361567#2`、`679361567#2_m3_north`，与现有热点的 `measurement_edges` 一致。按真实 `motion.edge_id` 归属统计；入口、公园道路和 SUMO 内部连接道路不计入核心区域分母。实验同时保留全场完成和受阻信息，避免遗漏外围问题。

直接复用后端 `visual_state`：正常、繁忙、计划内停留、明显拥挤和高风险拥挤。橙色 `crowded` 和红色 `high_risk` 是拥挤人数的组成部分。计划内停留本身不触发拥挤；计划停留者如果密度已满足橙色或红色判定，仍按现有规则计入。

现有橙色阈值为个体局部密度至少 1.5 人/平方米。红色为局部密度至少 4 人/平方米持续 5 秒，或局部密度至少 3.5 人/平方米且速度低于 0.2 米/秒同时持续 5 秒。现有密度采用同道路个体邻域近似；这些阈值是工程分类，并非伤害概率。区域平均密度、旧热点 `process_state` 和本次持续拥挤事件分别保留含义，不混用阈值。

## 持续拥挤规则 v1

在同一核心区域，以下条件连续成立至少 10 个仿真秒，即确认一次 `sustained_core_crowding`：

1. 橙色人数与红色人数之和不少于 10 人。
2. 该人数占核心区域全部当前行人的比例至少 20%。
3. 核心区域行人状态和密度数据有效，连续样本间隔不超过 0.5 秒。

分母包括正常行走、计划停留及受阻者，只统计当前仍在核心区域的行人；不使用全场总人数、地图渲染抽样人数或浏览器视野内人数。核心区为空时条件不成立。

规则必须在后端每个仿真步上计算。实验服务当前较低频率的观测采样不能直接证明“连续 10 秒”；后续接入时应上传每步累计得到的事件结果，前端只读取和展示。

计时、结束和缺失处理：

- 记录条件首次成立时间与确认时间。例如 120 秒起持续满足，130 秒确认。
- 任一人数或比例条件不满足，连续确认计时归零；已经确认的片段在第一个不满足的采样时刻结束。
- 只累计已达到 10 秒的片段，持续时间从片段首次满足时开始计算，包含确认前 10 秒。结束时刻的采样精度为 0.5 秒。
- 观察窗口结束时仍满足的片段标记为右截断，表示只知道截至观察终点的持续时间。
- 初始化 0.5 秒帧保留原始记录，但不参与正式判定，因为此时密度尚未就绪。第 1 秒及之后的未知密度或采样断档必须中断连续性，不能当作安全或跨缺口累计；缺口处结束的片段同样标记截断。
- 重复收到同一时刻同一数据不会增加持续时间；倒序或互相矛盾的数据拒绝计算。
- 正式观测完整且没有确认片段时，发生标志为 `false`；有确认片段时为 `true`；存在缺失且没有确认片段时为 `null`，报告为证据不足。

多轮出现频率以可判定的有效轮为分母，同时列出缺失、失败或中止轮数；它表示预设仿真条件下的样本频率，不直接外推真实世界发生概率。

## 结果指标

| 指标 | 明确含义 |
|---|---|
| 持续拥挤是否出现 | 上述规则在该轮正式观测窗口内是否得到确认 |
| 首次确认时刻 | 第一次达到连续 10 秒条件的仿真时刻 |
| 持续拥挤时长 | 已确认片段的观测时长之和，附截断标志 |
| 拥挤人数峰值 | 核心区橙色和红色人数之和的最大值 |
| 高风险拥挤人数峰值 | 核心区红色人数最大值 |
| 核心平均密度峰值 | 核心人数除以三条核心道路的可行走面积；与个体局部密度分开显示 |
| 行程完成率 | SUMO 正常完成行程人数 / 本轮计划总人数；包括计划中尚未完成的行人，移除者不算完成 |
| 95% 行程完成时间 | 从仿真起点算起，首次达到 95% 完成率的时刻；未达到为 `null`，显示“观察窗口内未达到” |
| 全场受阻与控制排队 | 配合核心指标观察外围代价，不仅按核心密度下降判断效果 |

“行程完成”保持当前模型语义，不额外设置安全区，也不将这些指标改称到达安全区的紧急疏散时间。所有轮使用相同的指标定义、观察窗口和事件规则版本。

## 第 2 类的控制边界

本期优先允许 `set_inflow_rate`，目标限定为三个实际入口：西侧 `178411801#0`、南侧 `177931018#0`、西侧中部 `monument_m3`。放行比例是相对标称入口吞吐的令牌桶比例，不是“停止该比例人数”。

控制时段限定在正式观测开始后、800 秒计划散场开始前，动作到期时间不得超过 800 秒。现有限流按下一条路径是否为入口道路选择对象，不额外识别进出方向；限制在入场汇聚阶段可避免把散场者也当作入场者限流。后续若扩展散场阶段的入口控制，应先补充方向识别。

阶段 0 只用人工指定的有限时长限流检查实际执行及到期释放，不据此承诺策略改善，也不调用大模型。后续第 2 类从真实观测生成并保存固定策略，然后使用相同场景与成对种子从头验证。信号 agent 的 0/1 机制与 xw 方法具体实现留待后续；xw 保留统一输入输出适配接口即可。

## 校核与复现

使用 SUMO 1.27.0 完成以下四项真实运行。时间均为仿真时间；表中短时运行不用于比较行程完成效果。

| 校核 | 种子 | 实际观测终点 | 持续拥挤 | 拥挤人数峰值 | 完成情况 |
|---|---|---|---|---|---|
| 700 人完整基线 | 20260908 | 1800 秒 | 130.5 秒首次确认 | 477 人 | 140/700，完成率 20%，未达到 95% |
| 100 人稀疏对照 | 20260908 | 1194.5 秒，全部完成后结束 | 未出现 | 0 人 | 100/100；95% 完成时间 1168 秒 |
| 700 人第二种子短时校核 | 20260909 | 360 秒 | 136.5 秒首次确认 | 625 人 | 尚未到计划散场阶段，不作完成效果比较 |
| 700 人限流执行校核 | 20260908 | 300 秒 | 130.5 秒首次确认 | 578 人 | 尚未到计划散场阶段，不作完成效果比较 |

100 人对照最多有 100 人处于计划停留状态，但没有橙色或红色拥挤，支持将正常停留与持续拥挤分开。两个种子下的 700 人运行均确认事件，支持保留 700 人为首个预设；现有校核数量不足以给出稳定的出现频率。

完整基线中，持续拥挤从 120.5 秒延续至 1800 秒观察终点，已观测持续时间为 1679.5 秒，终点截断。结束时仍有 560 人未完成行程，全场平均速度为 0，低速受阻人数为 483。这是当前场景下需要保留的严重残留受阻结果，不能将未完成的 95% 完成时间填成 1800 秒，也不能据此保证现有限流一定能改善。后续策略比较应同时看核心拥挤、全场受阻和行程完成指标。

限流校核在 120 秒向西侧入口施加比例 0.45、持续 120 秒的动作。真实暂缓放行人数峰值为 57；240 秒到期及之后的受控暂缓人数均为 0。该轮与同种子基线在控制前的全部统计样本一致，验证了成对比较的初始一致性。此校核只证明动作能执行和释放，不作为有效策略推荐。

四轮人口守恒检查均通过，无未知消失行人；按最终规则从原始 CSV 重算后，正式观测均无未知密度和采样断档。早期归档报告可能尚未排除初始化帧，统一以 `docs/validation/during_stage0.json` 中的最终规则及重算结果为准。相关规则与原有行人状态测试通过 32 项测试、5 项子测试。

脚本：`scripts/validate_during_preset.py`。它使用独立的 SUMO/TraCI 进程，不启动 WebSocket 服务、不调用模型；每轮记录正式需求、生成的人口、全部原始运行数据和 0.5 秒统计。脚本会检查实际计划人数、人口守恒、资源指纹及清理结果。

```bash
python scripts/validate_during_preset.py --counts 700 --seeds 20260908
python scripts/validate_during_preset.py --counts 100 --seeds 20260908
python scripts/validate_during_preset.py --counts 700 --seeds 20260909 --duration 360
python scripts/validate_during_preset.py --counts 700 --seeds 20260908 --duration 300 --variant metered
python -m pytest -q tests/test_during_crowding.py tests/test_crowd_visual_state.py
```

在当前电脑上使用已有 `/opt/miniconda3/envs/sumo/bin/python`。原始数据位于 `runs/during_stage0/` 和对应的独立 `runs/run-.../` 目录；小型校核摘要另存于 `docs/validation/during_stage0.json`。

原始轨迹与 CSV 由仓库忽略规则排除，保存在本机；校核摘要保留每轮运行 ID、路径和 CSV 校验和。脚本默认只校核首个种子；后续正式五轮实验需要显式指定预设的全部五个种子，不能将上述不同目的的校核混算为五轮实验。

预设资源指纹覆盖路网、需求来源、热点、人口画像、状态阈值、仿真与观测配置。资源变化时脚本停止并提示重新校核和升级预设，不能直接沿用旧结果。
