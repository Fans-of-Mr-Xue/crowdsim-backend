# 定向新闻采集

数据治理页面 `/home/crowdsim/dataGovernance` 已接入真实新闻采集与 MongoDB。
配置、任务状态和新闻正文保存在数据库；浏览器只保留事前任务定义等原有界面配置。
页面每 5 秒轮询最新状态，也支持手动刷新。采集中已通过校验的新闻立即可见，刷新或关闭
页面不会停止后端任务。链接查询参数 `task` 保存当前聚焦任务，点击任务会切换案件、地图边界、
配置与新闻列表。采集配置支持收起，收起后仅显示一行任务序列与待完成任务数；
补充原文链接和地区匹配词收在「更多设置」中。

## 独立启动

保持现有 MongoDB 连接或数据库 SSH 隧道可用，在后端根目录执行：

```sh
./run_crawlers.sh
# 或使用自己的 Python 环境
python -m data_service.crawlers --host 127.0.0.1 --port 8769 --concurrency 4
```

默认在 **8769** 提供新闻任务 HTTP 接口并启动 4 个并行任务消费者。
不启动、不连接 SUMO，也不依赖模型或 8768 数据 HTTP 服务。
数据库配置继续读取根目录 `.env` 中的 `CROWDSIM_MONGO_*`，前端不传递数据库密码。
`./run.sh` 的统一启动会启动或复用 8769；采集服务启动失败或运行中退出不会停止 SUMO、
对话和其他数据服务。统一入口 Ctrl+C 仍会关闭它本次创建的服务。

可在其他终端或机器上增加只消费队列的进程，连接同一数据库即可：

```sh
./run_crawlers.sh --worker-only --concurrency 4
./run_crawlers.sh --once --concurrency 2
./run_crawlers.sh --task <任务ID>
```

`--once` 处理当前可领取任务后退出；`--task` 只领取指定任务，已被其他消费者领取时退出。
它们均不启动 HTTP 端口。默认服务和 `--worker-only` 持续等待新任务，但每个采集任务执行一轮；
目前不包含自动周期性重新采集，可由外部调度器提交追加采集需求。

每个任务通过 MongoDB 原子操作领取，租约 90 秒，每 15 秒续租。
多个进程不会同时领取同一任务；进程异常退出后，其未完成任务在租约过期后可重新领取。
再次领取时复用已保存新闻，通过唯一索引防止重复入库。访问超时为 25 秒，连接类失败重试一次，
每个站点串行访问且间隔至少 0.7 秒，并尊重 robots.txt 和站点声明的 crawl-delay。

## 数据集合

所有案件的新闻共用 `crowdsim.news_articles`，没有按案件建立不同集合。

| 集合 | 内容与索引 |
| --- | --- |
| `news_articles` | 原文 URL、标题、正文、摘要、媒体来源、UTC 发布时间、归集时间、主题、任务地区、`eventId`、首次采集 `taskId`。按案件 + 链接、规范化标题、规范化正文分别建立唯一索引；案件 + 发布时间索引用于检索。 |
| `news_collection_tasks` | 事件、地区 ID/匹配词、关键词、新闻发布时间窗、累计目标、本次条数、补充链接、状态、计数、租约、版本及删除时间。同一 `eventId` 只有一个主任务，数据库部分唯一索引约束；旧重复任务仅保留归档及跳转信息。 |
| `news_crawler_workers` | 在线消费者心跳和并发数，不存新闻。45 秒失联即视为离线，TTL 索引清理过期记录。 |
| `news_collection_control` | 旧重复任务升级的临时租约，防止多个采集进程同时迁移。 |

集合及索引由采集服务启动时自动建立。`eventId` 由规范化事件名称与地区 ID 生成，同名同地区
的后续提交更新同一个采集任务；不会按事件名称的子串将不同案件强行合并。
采集地区直接读取环境库，提交时后端验证 `regionId` 属于未删除的数据库地区，并采用环境库的位置说明。地区旁可进入环境库，新建保存后返回并选中该地区，保留采集草稿。
前端「本次采集条数」与 POST 请求 `maxRecords` 表示本次新增需求，为 **1—500**。
响应中的 `maxRecords` 是累计目标，`lastBatchSize` 是上次提交的新增条数。
已有 5 条新闻，再提交 5 条，原任务目标变为 10 条；运行中追加会保留尚未完成的需求。
任务已完成、不足、失败、停止或删除后再次提交，则以实际已入库数量加本次条数为目标。
多个提交者并发追加通过任务版本比较并更新，累计需求不会互相覆盖；旧版本爬虫结束时会重新
排队处理追加目标，不能把追加任务按旧目标标为完成。时间范围合并为覆盖新旧窗口的区间，
关键词采用用户最终保留的标签（包括删除和新增），补充链接优先保留新配置并在 50 项限额内合并。每个任务展示合并时间窗内的
案件新闻，最多展示累计目标条数。

同一事件只有一个可见任务。服务启动时自动合并原有重复任务，保留最早任务 ID、旧 ID 跳转
以及全部新闻；最近任务已停止时保持停止，不因迁移自动重启。重复任务的历史记录不参与队列。
前端可删除选中的采集任务，后端逻辑删除、移出列表并撤销爬虫租约，已入库新闻保留。
再次提交同一事件会恢复原任务并追加采集，删除不会清空新闻或重置去重索引。

## 新闻发现与筛选

采集页在初次填写或更改事件、地区、时间范围后自动请求 `POST /api/crowdSim/news-collection/recommend-keywords`。
后端验证环境库地区，使用实际地区名称、说明和事件时间调用共享 `JsonModelClient`（`CROWDSIM_LLM_*`），返回 `keywords`、`source: llm` 与 `model`。
推荐标签可删除，也可回车新增，最多保留 20 项；删除项不会因重新推荐自动恢复。已保存案件保留用户标签，推荐结果不自动创建任务。
推荐请求最长 60 秒，同服务最多两个模型推荐请求同时执行；模型失败返回 502，前端保留现有标签并提供重试与手动新增，不伪造推荐结果。

- 通过 Bing 网页搜索及百度新闻搜索发现链接。百度请求携带时间范围；搜索结果还会再次检查原文发布时间。
- 可在前端按行补充最多 50 条公开新闻原文链接，先抓取这些链接，再搜索其他来源。
- 郑州洪涝历史案例使用 `crawlers/zhengzhou_seeds.json` 中的 50 个已知原文链接作为发现入口。
  这个文件只保存 URL；正文、标题、时间和摘要每次均从真实网页提取，不将旧前端样例内容入库。
- 只有正文不少于 120 字、包含目标地区匹配词以及至少一个地区以外主题关键词，且发布时间在
  指定窗口内的报道才入库。时间来自网页元数据、结构化数据或新闻时间区域；不能确认时间的记录排除。
- 去掉链接追踪参数和片段，规范化标题和正文，三个独立唯一索引防止同链接、同标题和同正文重复。
- 不生成新闻、不虚构可信度分数。原文提及已核验地点时，保存 `locationPoints`，
  每个地点包含名称、WGS84 经纬度、定位精度、匹配词、原文片段和 OpenStreetMap 来源链接。
  一篇报道可关联多个地点；`locationPrecision=mentioned_place` 表示报道提及这些地点，
  不表示记者或事件的精确坐标。医院区域、水库区域、隧道路段和乡镇使用代表点，并标注精度。
- 地点目录 `crawlers/news_places.json` 按地区 ID 隔离，目前核验了郑州的沙口路站、海滩寺站、
  郑大一附院河医院区、京广北路隧道、郭家咀水库和米河镇。仅凭“地铁5号线”、城市名或
  未指明院区的医院名不定位具体地点；未匹配目录时保持 `locationPrecision=task_region`。
  可扩展目录并提高 `version`，不按文章序号或主题随机分配坐标。

地图与态势研判共用高德底图，并将 WGS84 点位和行政边界转换为 GCJ02。地图按实际地点归并
关联新闻；点击点位查看标题、原文依据和坐标来源，点击新闻的「地图定位」适配该篇涉及地点。
默认适配当前页新闻点位，也可切换到完整案件边界；搜索与来源/主题筛选同步更新点位。
没有具体地点的报道在地区中心归集，并标注尚未定位。

为已入库新闻补全地点，不重新爬取、不改变正文、去重标识和任务状态：

```sh
./run_crawlers.sh --enrich-locations
./run_crawlers.sh --enrich-locations --task <任务ID>
```

补全操作可重复执行。新采集的新闻自动执行相同的地点匹配，坐标和依据持久化在同一新闻集合。

搜索源可能返回验证码、robots 禁止、动态页面或网络错误，这些情况会记录并跳过。
不足目标条数时返回 `partial`，一条合格新闻也没有时返回 `failed`，不会用重复内容凑数。
网页正文上限 4 MiB；当前不提供登录、验证码处理、浏览器动态渲染、OCR 或语义相似度去重。

状态为 `queued → running → completed / partial / failed`，前端支持将排队或运行任务设为
`cancelled`。已保存新闻保留；任务下一次检查租约时停止抓取，正在进行的网络请求可能需要等待超时。
部分结果任务可以恢复其案件配置、补充链接后提交本次新增条数，继续追加采集。

## HTTP 与代理

前端开发代理将 `/api/crowdSim/news-collection/*` 转到 `http://127.0.0.1:8769`。
可用前端服务端变量 `CROWDSIM_NEWS_API_TARGET` 修改目标并重启 Vite；静态部署需要配置同一路径的反向代理。
8768 数据服务也注册了同样的任务接口，部署时可将 API 代理到更新后的 8768，并独立运行 `--worker-only`。

所有成功响应使用 `{"data": ...}`，失败使用 `{"message": ...}`。
兼容无 `/api` 前缀的 `/crowdSim/news-collection/*` 路径。

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | `/api/crowdSim/news-collection/status` | 8769 服务与数据库连通性 |
| GET / POST | `/api/crowdSim/news-collection/tasks` | 分页任务列表 / 首次创建或对同事件追加采集 |
| GET | `/api/crowdSim/news-collection/tasks/{id}` | 当前任务详情与实时已入库条数 |
| DELETE | `/api/crowdSim/news-collection/tasks/{id}` | 删除任务并停止采集，保留新闻；重复删除可安全重试 |
| GET | `/api/crowdSim/news-collection/tasks/{id}/news` | 案件时间窗内去重后的新闻，分页，不返回完整正文 |
| POST | `/api/crowdSim/news-collection/tasks/{id}/cancel` | 停止任务，保留新闻 |

列表与新闻支持 `page`、`page_size`，每页最多 100 条。前端任务每页 20 条、新闻每页 50 条，
搜索及来源/主题过滤针对当前新闻页。400 为输入错误，404 为任务不存在，503 为数据库暂不可用。
POST 首次创建返回 201；追加或恢复返回 200，响应 `operation=created/appended`、
`requestedRecords` 说明本次操作。删除后详情和新闻接口返回 404，重新提交后恢复可访问。
请求示例：

```json
{
  "eventName": "河南郑州“7·20”特大暴雨洪涝",
  "regionId": "zhengzhou-portrait-region",
  "location": "郑州 · 河南 · 中国",
  "regionKeyword": "郑州",
  "keywords": ["暴雨", "洪涝", "地铁5号线"],
  "timeRange": ["2021-07-20 00:00", "2022-01-21 23:59"],
  "maxRecords": 30,
  "seedUrls": [],
  "configSource": "人工配置"
}
```

无时区的配置日期按北京时间解释，数据库保存 UTC 并明确返回偏移量，前端按北京时间展示。
