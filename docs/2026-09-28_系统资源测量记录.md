# CPU、GPU 与热状态记录

## 使用

正常 `bash run.sh` 重启后端即可，不安装依赖，不要求 sudo，不需要修改前端。
每轮初始化成功后，每约 5 秒墙钟时间在独立线程中采样，输出到
`runs/<run_id>/performance.system.jsonl`。READY/PAUSED 时也记录，以便对照空闲和运行；
FINISHED/ERROR 后下一次采样自动停止，重置/关闭时唤醒线程保存尾样本并退出。
强制杀进程不能保证尾样本保存。不会每步调用系统工具，也不调用 TraCI。

需要重启后端后再运行一轮完整仿真；旧 runs 无法补录资源数据。
建议固定人数、倍率与视角，记录时关闭不必要的网页，并保持相同充电与散热条件。

## 指标与边界

| 字段 | 含义及范围 |
| --- | --- |
| host.cpu.busy_percent | macOS host_statistics 相邻样本 CPU tick 差分，整机所有逻辑核归一化 0–100%；不是单个进程 |
| host.processes.groups | Python 后端进程、其 SUMO 子进程、所有浏览器/WebKit 相关进程、WindowServer、Cursor/Codex 进程分组 |
| cpu_one_core_percent | 相邻 ps 累计 CPU 时间差/墙钟时间，100% 是占用一个核，可超过 100%；PID/启动时间变更时不拼接差分 |
| rss_bytes / rss_bytes_sum | 进程驻留内存及分组求和；共享页可能重复计数，不是整机物理内存总占用 |
| host.gpu.devices | Apple AGX 驱动快照：整机 Device/Renderer/Tiler 利用率和 in-use 系统内存；三种百分比不相加，采样周期由驱动决定，不是完整 5 秒平均 |
| host.thermal.pressure | NSProcessInfo.thermalState：nominal、fair、serious、critical；系统热压力，不是摄氏温度或已测得的降频百分比 |
| host.battery.temperature_celsius | AppleSmartBattery 顶层 Temperature/100，电池温度；同时留原始值与转换来源，不是 CPU/GPU/机壳温度 |
| host.battery.charging / external_power_connected | 是否正在充电/接外部电源 |
| host.chip_temperature | 当前 CPU/GPU 摄氏温度均 null，明确标记 unavailable 和原因；未实现不可靠的私有芯片传感器访问 |
| collection_wall_ms | 单次系统数据采集墙钟耗时，不包含该行磁盘写入；不是采样线程的 CPU 时间 |

浏览器组不能准确归因于某个网页；WebKit 也可能属于 Codex 或其他嵌入式浏览器。
采集发生在后端所在电脑；如果未来浏览器改在另一台电脑运行，这份日志不会包含远端浏览器的资源消耗。
WindowServer 与 GPU 均受桌面其他应用影响，不能直接当成本项目前端独占开销。
首次 CPU 样本仅建立基线，返回 null；退出进程的末尾 CPU 时间可能遗漏，新进程需第二次采样才能差分。
热压力 normal/nominal 不意味着机身不热，也不能直接证明没有任何频率变化。
未记录电功率、累计能耗、电池放电功率或芯片温度；CPU/GPU 利用率不能直接换算瓦特。

每行包含 run_id、墙钟时间、采样开始墙钟时间、采样开始时的仿真时间/状态/人数/倍率。
不同传感器是顺序读取而非同一瞬间；过渡窗不宜当作稳态结果。按墙钟时间关联原有前后端性能日志。
只记录相关可执行文件的 basename、PID 与资源值，不保存完整命令参数、网页地址、其他进程列表或整个 IORegistry。

## 开销和容错

每次仅执行一次 ps、两次限深度 ioreg，其余为只读系统 API；每条命令有 1.5 秒超时。
独立线程运行，不在仿真每步主路径执行这些查询；仍有少量 CPU/GIL/磁盘竞争，不宣称零开销。
不保存无限增长的内存历史，保留上一份相关进程/CPU 计数用于差分，数据逐行落盘。
关闭时最多等待 10 秒回收采样线程；正常应很快完成，不留下 powermetrics 常驻进程。
单项接口失败写 unavailable 和异常类型，其余项继续；系统日志写入失败停采，诊断原因保存在
`get_status.performance.system.error`/最终 summary，相应失败不导致仿真 ERROR。
系统采集目前只支持 macOS；其他平台写一条 unsupported 说明后退出，原有前后端性能测量仍可用。
AGX/电池 IORegistry 字段不是稳定公共接口，系统更新后可能缺失；不会将缺失记为零。

`CROWDSIM_SYSTEM_PERF=0 bash run.sh` 仅关闭新增系统测量。
`CROWDSIM_PERF=0 bash run.sh` 关闭原有测量以及新增系统测量。
配置在 manifest.system_performance_measurement 中保存；running 字段是写入时快照，最终状态看 summary。

## 来源与验证

热压力使用 [Apple NSProcessInfo.thermalState](https://developer.apple.com/documentation/foundation/processinfo/thermalstate-swift.property)。
CPU 结构和常量来自本机 macOS SDK 的 mach/host_info.h；GPU 字段直接核对本机 AGXAccelerator 输出。
电池字段是 AppleSmartBattery 驱动诊断数据，必须与芯片温度分开解释。

新增测试覆盖进程归属、CPU 差分/PID 复用、缺失数据、单项失败隔离、后台关闭、结束自动停采、
写入失败、非 macOS 降级、禁用与重复启动；回归测试继续使用临时目录和小型 SUMO 场景，
不运行用户完整纪念塔任务，不改人数、路径、行为、步长、倍率或渲染。

验证结果：新增 8 项测试和既有 43 项后端回归测试通过。既有小型 SUMO 开关对照中，
12 步轨迹、速度、五状态和压力状态相同。独立硬件采样测试成功读取 CPU、GPU、
热压力、电池温度和相关进程；三次采集墙钟耗时约 61/91/87 ms，正常关闭后线程退出。
这是短时功能验证，不代表高人数完整任务下的固定开销，后续应以新日志实际结果分析。
