# 事前三模型原型：纪念塔路网

本版接入分区流量守恒、JuPedSim CFS、JuPedSim Social Force 三种实际计算实现。现有“预测方法对比”页面可以勾选模型、运行同一份任务、切换地图与曲线，并显示逐人模型的行人位置。目录只推荐这三种；旧方法仅保留历史任务兼容。未安装引擎、规模超限或某个模型失败时显示具体原因，不用其他算法代替它生成结果。

## 需求对话、模型库与实验控制台

`GET /api/crowdSim/pre-assessments/catalog` 提供统一模型目录、正文说明、七类共同输入和十三项实验配置及校验范围。内容由 `data_service/prediction/consultation_catalog.py` 维护，前端模型库、示例、需求界定控制台均从接口读取。需求页初始化即加载配置契约，不依赖展开控制台。

需求页五项为研究目标、活动与范围、通用输入、预期输出、实验控制台。原“场景条件”合并为通用输入中的背景备注；旧文字步骤保留在记录中，不再作为参数编辑器展示。范围地图读取已选环境对应版本的路网。对话先确认输出并立即同步指标，再介绍和确认模型、逐项补输入；旧版只有文字步骤的方案需要重新选择实际模型。相关案例库支持至少两个记录时提供两条独立建议。

实验选择保存在 `components.research_plan.experiment`，与已有 `forecast_setup` 双向同步；预测接口省略方法或参数时使用任务中保存的选择。明确的参数赋值由后端确定性校验、生成完整字段修改，避免只生成“将修改”的文字；含歧义、条件或其他任务的请求仍交由模型理解。默认值标为工程假设。

实验重复次数为 1–5，默认 1；每轮种子为 `(基础种子 + 轮次 - 1) mod 2147483648`，同轮各模型共用种子。后端保留 `replications` 和 `repeat_summary`（峰值人数、密度、队列、离场等指标的均值与范围）；旧单次结果结构仍可读取。地图和曲线切换整轮结果，不平均轨迹。某个模型任一轮失败时，该模型的不完整批次不进入比较，并明确失败轮次。

验证包括 78 项相关后端测试（含真实三引擎各重复两次、HTTP 保存重读、共同种子、人数守恒与参数持久化）、前端相关测试和生产构建。实际页面核对地图已有路网、五项编号及实际实验参数编辑入口。

## 快速运行

在后端目录、Python 3.11–3.13 环境中安装已有后端依赖，再安装预测扩展（本机已在 `.venv-backend` 安装 JuPedSim 1.4.2）：

```sh
python -m pip install -r requirements.txt
python -m pip install -r requirements-prediction.txt
python scripts/run_prediction_demo.py
```

JuPedSim 的上游发行包会同时安装桌面可视化依赖。只运行本项目的无界面计算时，可用以下方式替代第二条命令；项目不调用其 Qt/VTK 可视化组件：

```sh
python -m pip install 'numpy>=2.2,<3' 'shapely>=2,<3' 'pyproj>=3.6,<4'
python -m pip install --no-deps 'jupedsim==1.4.2'
```

脚本默认使用上海人民英雄纪念塔场地，生成 `outputs/three-model-demo.json` 与可离线打开的 `outputs/three-model-demo.html`。它执行与正式接口相同的 `compute_comparison`，不需要 MongoDB、联网取地图或调用大模型。`--scene synthetic` 仅保留给简单障碍物回归测试。

正式页面继续使用 `/api/crowdSim/pre-assessments` 接口、数据库任务快照和异步进程池。重启使用该 Python 环境的数据服务后，新模型目录生效。没有修改已有数据库任务的人数或时间窗。

## 纪念塔场地与本次试算

- 路网直接读取 `data_service/resources/geography/shanghai-monument-sumo.geojson`，即已有 `bund.net.xml` 导出的 23 条步道和 18 个路口步行面。沿用现有热点禁行设置，没有把整个公园边界填成可行走面。
- 聚集点来自 `config/crowd_hotspots.json` 的纪念塔锚点，吸附到可行走网格。可在正式页面地图上重新指定聚集点。
- A、B 是既有 `park_entry_edges` 对应步道上的模拟吸收区，分别为西北侧、南侧连接；不是官方园门编号，也不是实测出口断面。本次只有两条通道，不另造 C 出口。
- 修复网格切分只保留最大碎片而切断弯曲步道的问题。SUMO 步道与路口导出面之间的毫米级缝隙用 **1 厘米**容差闭合，随后再扣除显式障碍与围栏。真正的米级断路保持断开。
- 保留最大连通部分约 **1652.16 ㎡**；仍断开的约 **55.05 ㎡**没有参与计算。结果记录这两项面积、连通分量数量和几何处理容差。
- 试算假设：初始 **80 人**；前两分钟 **8 人/分钟**，之后无新增；平均驻留 **1 分钟**；模拟 **5 分钟**；统计网格 **4 米**；种子 **42**。这些不是现场测量或历史事件还原。

当前保存的一次运行结果：

| 方法 | 第 5 分钟场内人数 | 累计离场人数 | 人数守恒误差 |
| --- | ---: | ---: | ---: |
| 分区流量守恒 | 82.03 | 13.97 | < 10⁻⁸ |
| CFS | 41 | 55 | 0 |
| 社会力 SFM | 24 | 72 | 0 |

总人数为 80 + 16 = 96，场外队列均为 0。差异表示不同运动假设产生了不同结果，不能据此判断哪种更准确。

## 输入与输出

| 输入 | 使用方式 |
| --- | --- |
| WGS84 场地边界、步道宽度/可行走面、障碍物 | 转为局部米制坐标；三者使用同一可行走区域。守恒模型构成连通网格，逐人模型使用其几何并统计回相同网格 |
| 初始人数、初始驻留比例 | 守恒模型按面积分配连续期望人数；CFS/SFM 按同一种子生成相同的不重叠初始位置，初速为 0 |
| 到达曲线、入口比例 | 同一到达曲线积分；逐人模型取累计需求的整数部分，未入场者进入场外队列 |
| 聚集点、平均驻留时间 | 接近聚集区后驻留，采用指数驻留假设；随后选择出口，逐人模型保持每人相同的行为随机抽样规则 |
| 出口位置、通道服务能力 | 吸附网格作为出口吸收区；共同使用外部通道服务限制。真实出口宽度与形状尚待测绘 |
| 自由步速、路线成本敏感度 | 三者共用；逐人模型内部由引擎计算避让与速度变化 |
| 半径，默认 0.20 米 | CFS/SFM 的几何占用参数 |
| CFS 期望时间间隔，默认 1 秒 | CFS 的速度—间距关系参数 |
| SFM 速度响应时间，默认 0.5 秒 | SFM 的目标速度响应参数；其余采用并记录 JuPedSim 默认值：质量 80 kg、两类排斥幅值 2000、作用距离 0.08 m |
| 中观拥挤密度上限、回堵波速 | 仅用于中观模型的收发容量；不会截断逐人模拟的统计密度 |

共同输出：场内人数、场外队列、累计到达和离场、网格密度、全场平均密度、采样局部最大密度、平均速度、相邻切片间平均离场流量、首次采样预警时刻。逐人模型另输出每个保存切片的行人位置与阶段，可在地图叠加。

风险、压力、方向混杂保留兼容已有结果页，但仅作探索指标。压力为密度乘速度方差，不是接触力；中观运动状态方向和微观实际速度方向的口径不同。模型比较优先看人数、密度、排队和离场，不能把这些指标当事故概率。

## 首版边界

逐人模型保留任务完整时间窗（平台统一支持 1 分钟至 12 小时），不再设置 60 分钟门槛，也不把已经离场的人乘以后续全部时间步。单层连通场地约束仍保留；CFS 运动积分步长为 0.05 秒，SFM 为 0.01 秒。社会力使用较细步长是为修复窄通道压力测试中的数值越界，输出采样间隔仍然一致。

当前服务预算为同时在场 3000 人、实际在场人数逐步累计 20 亿人步、单模型每次 1800 秒、每次保存最多 50 万条位置。分别由 `CROWDSIM_MICRO_MAX_ACTIVE`、`CROWDSIM_MICRO_MAX_AGENT_STEPS`、`CROWDSIM_MICRO_MAX_SECONDS`、`CROWDSIM_MICRO_MAX_SAVED_POSITIONS` 调整，须重启服务。它们是资源上限，不是承诺任意几何与人数都能完成。超限不截短研究时段、不减少人员、不发布该模型的局部结果；其他完整模型可查看。调整预算会改变缓存键。

性能优化包括批量空间查询、仅在行为切换时访问模型状态、入口附近的局部占位检查，以及复用单一引导阶段。目标确定时缓存 JuPedSim 生成的几何航点，将直线段等分为不超过 2 米的子段，距下一航点 1 米内推进；两个微观模型采用相同引导规则，运动与避让仍由原生引擎逐步计算。此路径策略不同于旧版每步重算全程路径，CFS 版本为 1.1.0、SFM 为 1.1.1，不能把轨迹差异全部归于 CFS / SFM。路网几何、人员数和研究时段不改变。入场同时检查引擎的上一步邻域索引，避免新位置虽然空闲却被引擎的旧索引拒绝。

运行状态通过后台进程每秒输出、主进程定期保存的进度传回界面，包含模型、重复序号和已模拟分钟数；没有伪造的剩余耗时估计。位置按配置的输出间隔保存，地图切换同一次实验的模型切片；守恒模型不合成逐人位置。

2026-10-23 本机验证记录（耗时受并行后台测试影响，不是平台吞吐保证）：

| 场景 | CFS | SFM |
| --- | --- | --- |
| 75 分钟合成广场，初始 5 人、2 人/分钟、在场预算临时设为 30 人 | 完整完成，累计需求 155 人 | 完整完成，累计需求 155 人 |
| 纪念塔 5 分钟，初始 100 人、87.04 人/分钟 | 旧版约 36.8 秒 → 当前约 6.3 秒 | 旧版约 31.8 秒 → 当前约 20.8 秒（当前使用更细的 0.01 秒步长） |
| 纪念塔初始 3000 人，1 分钟、无新增到达 | 完成，约 18.5 秒 | 0.05 秒步长曾越界；改为 0.01 秒后完成，约 61.3 秒 |

完整时间窗的手动回归入口：`PYTHONPATH=. .venv-backend/bin/python benchmarks/full_window_prediction.py --minutes 270`。默认采用纪念塔既有 SUMO 路网、初始 150 人、恒定每分钟 1 人、平均驻留 5 分钟，均为显式测试假设；可用 `--initial`、`--arrivals`、`--dwell` 调整负载。它不会修改数据库研究任务，也不把低负载验证等同于高客流验证。

三者的入口排队、驻留和出口选择均为本项目的情景控制器，CFS/SFM 负责逐人运动，不能把整套行为流程都称为原论文模型。未实现楼层切换、伤害预测、按年龄自动分配未经证实的行为系数、现场标定和误差排名。地图播放的是保存切片，不会伪造切片间轨迹。

## 依据

- 守恒离散思想：[Daganzo, Cell Transmission Model](https://escholarship.org/uc/item/0b6612tk)，当前为行人场景的工程适配。
- CFS：[Tordeux、Chraibi、Seyfried，2015，Collision-free speed model for pedestrian dynamics](https://arxiv.org/abs/1512.05597)，TGF’15。引擎为 JuPedSim `CollisionFreeSpeedModel`。原先登记的 PRE 94, 012312 是另一篇年龄组成实验论文，已纠正。
- 社会力思想：[Helbing & Molnár, 1995, Phys. Rev. E 51, 4282](https://doi.org/10.1103/PhysRevE.51.4282)。使用 JuPedSim 的平滑排斥 `SocialForceModel` 实现，不宣称原论文所有扩展项均已复现。
- [JuPedSim 官方文档](https://www.jupedsim.org/stable/)，本适配固定版本 1.4.2。
