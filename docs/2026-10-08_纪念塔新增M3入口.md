# 纪念塔新增 M3 入口

在现有 `scenarios/shanghai_bund/bund.net.xml` 上新增步行通道，连接目标按用户更正为 **H2 劣弧**。H1 是绕北、东、南侧的优弧，原步行边长 121.78 米；H2 是西侧劣弧，拆分前步行边长 19.83 米。未替换为下载的 OSM 路网。

## 几何与编号

原 J01—J25 编号保持不变，新增环道接入点编号 J26。

完整编号对应关系保存在 `scenarios/shanghai_bund/patches/monument_m3.numbering.json`；H2 南、北段分别标为 H2a、H2b，仍属于同一条 H2 劣弧。原有道路编号保持对应，共 34 个 SUMO 路段、26 个编号节点。

| 对象 | SUMO ID | 连接 |
| --- | --- | --- |
| J13 | `8417005112` | 原有公园路口，坐标 `(18585.94, 5843.03)` |
| J26 | `monument_m3_ring_junction` | H2 上新路口，坐标 `(18596.41, 5848.74)` |
| M3 | `monument_m3` | J13 → J26，行人可双向通行 |
| H2 南段 | `679361567#2` | J14 → J26，保留原边 ID |
| H2 北段 | `679361567#2_m3_north` | J26 → J08 |

J26 取 J13 到现有 H2 中心线的最近点，坐标按厘米取整。M3 中心线约 11.93 米；扣除两端 SUMO 路口区域后，普通步行 lane 长 6.90 米。M3 宽度暂取现有 M1、M2 相同的 2 米，允许类型仅为 `pedestrian`；新路口 walkingarea 宽 4 米。走向、位置与宽度均为手工建模假设，未经现场测绘确认。

新路在 H2 上建立实际共享节点和步行连接。H2 拆分后两条普通 lane 分别长 5.81 米和 9.02 米，中间路口部分由 walkingarea 表示。

## 同步配置

- `config/crowd_hotspots.json`：新增 `west_middle_gate`，入口边为 M3，方向为公园侧 `from`、纪念塔侧 `to`。入口共三条；目标与测量环道共三条 SUMO 边。
- 原西侧观景区拆成 H2 南、北两区，停留位置分别为 `[2, 3.81]`、`[2, 7.02]` 米。保留西侧总权重 6%，按可停留长度分为约 1.59% 与 4.41%；H1 五个观景区保持原配置。位置均留出两米端点余量。
- `bund_ped.rou.xml`：迁移唯一引用旧 H2 的背景步行路线，按原反向行走顺序经过 H2 北段、南段。
- `bund_hotspot.rou.xml`：重新生成 700 人需求。三个入口均用于进场和离场；自动入口选择、避堵候选、入口流量统计、外环统计通过配置自动纳入 M3。
- 原公园道路、生成位置、离场目的地、人数、活动时段设定及排除内环/地下道路的规则保持原设定。需求生成器按新路线重新计算首人从零出发的时间偏移，前端仍使用生成报告中的实际时间轴。

## 生成与检查

节点和道路补丁保存在 `scenarios/shanghai_bund/patches/monument_m3.nod.xml`、`monument_m3.edg.xml`。`scripts/add_monument_m3.py` 使用 netconvert 生成局部几何，并仅合并受影响的元素；保留原全网格式、投影、信号灯、无关路口、连接与人工加宽设置。H2 原端点的几何保持原状，仅更新拆分后的边引用。本次局部几何使用本机 netconvert 1.27.0 生成。

对修改前的旧网，可运行：

```bash
python scripts/add_monument_m3.py --input /path/to/original-bund.net.xml
python scripts/generate_hotspot_demand.py
```

已经存在完整 M3 时，新增脚本不重复添加。迁移旧 H2 需求和观景配置需采用本次更新后的版本；旧边上的停留位置需换算为拆分后的短边位置。

仅进行了代码级检查，未启动 SUMO 仿真、后端服务或前端。使用现有 Conda `sumo` 环境的 sumolib/traci 1.24.0 进行 XML 解析、配置加载、位置路由与需求生成测试。核验范围包括三个入口的双向可达性、M3 到全部生成道路和观景区的位置路由、观景范围、700 人存储需求的边引用与连续性、流量与核心区统计、自动需求人数和时间轴。
