# 事中阶段 3：大模型策略生成与固定策略重跑

本阶段在第 1 类真实观察、聊天需求澄清和参数确认流程之后，接入第 2 类。实现日期：2026-10-14。首次实现只完成代码级检查；随后于 2026-10-14 至 15 日完成真实模型与 4 轮 SUMO 验收，详见 [真实验收报告](during_stage3_acceptance.md)。功能流程通过，策略效果有取舍，不能宣称整体改善。

## 用户流程

1. 继续原有需求澄清与完整方案确认，保存并启动无控制观察。单独说“事中”仍是空白需求，不自动采用纪念塔。
2. 等待推演实验所有平行实验结束。至少有一轮完整有效的正式观察后，在聊天请求“生成限流策略”，或使用侧栏按钮。原来只选择第 1 类的实验也可以显式继续生成策略，无需篡改原推演需求。
3. 服务端从当前对话的来源实验读取有效轮次、真实指标、时间序列摘要及控制边界；前端通过原有大模型入口生成结构化策略，再交给服务端校验。模型调用失败、JSON 不完整、动作不支持或来源变化时，明确报错，不提供假策略或自动降级策略。
4. 展示生成理由、每个入口的控制时段和放行比例、效果假设、限制、模型标识、有效种子及被排除轮数。用户可说明新的要求并重新生成；开始重新生成就撤销旧确认，失败也不会保留旧确认供误提交。
5. “确认当前策略”只确认；“保存策略验证方案”创建独立验证实验；在方案页“启动实验”才实际重跑。确认和保存不会自动启动。
6. 验证实验使用来源中全部有效轮次的相同种子、人数、资源版本、时长和判定规则，从头运行同一套策略。来源观察保持原样；验证实验和来源都在同一对话历史列表中，可返回来源再次生成策略。
7. 查看真实运行指标、动作计划与实际施加时间、回执，以及同种子配对报告。支持原有暂停、继续、取消本轮、刷新、页面恢复和聊天解读。

策略草稿暂存在当前浏览器；保存后的策略、生成记录、来源证据快照和来源确认需求归档在后端实验中。生成过程中不会创建实验。网络提交结果不明时保留幂等键并锁定草稿，可重试或从历史恢复，避免重复创建和启动。

## 执行边界

- 当前执行场景仍是已验证的纪念塔配置。聊天可记录其他要求，但不会把它们自动替换为纪念塔。
- 仅支持大模型生成 1～6 个固定 `set_inflow_rate` 时段。三个入口为西侧 `178411801#0`、南侧 `177931018#0`、西侧中部 `monument_m3`。
- `rate` 为相对标称入口吞吐比例，范围 0～1；不是停止某个比例的人数。
- 时间为绝对仿真秒，0.5 秒的倍数，至少持续 1 秒；开始不早于 1 秒，结束不晚于 800 秒。同一入口时段不能重叠。
- 调度器每个收到的仿真帧检查到期时段，不受原有 30 秒报告采样间隔限制。动作仍经已有 WebSocket 队列执行，实际施加可能晚于计划开始；报告记录两者，不声称精确同步。
- 动作新增 `endTimeSeconds` 绝对截止时间。传输延迟不会延长控制到期时间；过期指令在产生影响前拒绝，到期释放暂缓行人。旧的相对时长动作保持兼容。
- xw 预留统一生成方式字段和能力声明（`methods.xw=false`），请求实际执行会拒绝。第 3、4 类、信号 agent、自定义公式、散场方向识别和多轮自动优化未实现。

本功能使用内部控制器 `D2/during_fixed_replay`，与通用实验中的 `C2/LLM-OneShot` 区分。D2 运行中不调用模型，也不替换为阈值规则。公共 C0～C5 目录保持兼容，不能从普通创建接口直接绕过策略确认创建 D2。

## 服务接口与归档

沿用 `/crowdSim/control` 和 `X-CrowdSim-User`、`X-CrowdSim-Workspace` 隔离：

| 接口 | 作用 |
| --- | --- |
| `GET /experiments/{sourceId}/strategy-context` | 校验来源已结束且有有效轮次，返回指标、摘要、允许动作和证据指纹 |
| `POST /experiments/{sourceId}/strategy-preview` | 校验 `sourceFingerprint`、`strategy`、`generation`，返回可供确认的候选及指纹，不创建实验 |
| `POST /experiments/{sourceId}/strategy-replays` | 再校验证据和 `confirmedFingerprint`，以 `clientRequestId` 幂等创建验证实验 |
| 原有实验详情、启动、运行控制和报告接口 | 继续使用；报告增加 `strategyComparison` 和各轮 `strategyActions` |

`generation` 记录 `{method, model, request, rawResponse}`。`strategy` 记录名称、理由、效果假设、限制及入口时段。`duringReplay` 保存候选指纹、完整来源上下文及来源需求快照；不会把原观察的“无外部控制”误标成验证阶段的控制方式。普通创建接口拒绝携带 D2 或 `duringReplay` 的请求，启动前再次验证已存档的策略绑定。

## 比较口径

- 基线只使用正式、完成、人口守恒、指纹一致、持续拥挤观测覆盖完整的轮次。取消、失败和不完整轮次不进入配对种子。
- 验证轮还必须获得每个计划动作的成功回执。仅有 queued、拒绝、缺失动作或观测不完整时，不纳入效果配对。
- 显示同组聚集出现频率，以及首次确认时间、聚集持续时间、橙红/红色峰值、核心密度峰值、完成率、95% 完成时间、全场受阻、控制暂缓的配对差值。
- 差值为“策略轮减基线轮”。每项指标单独统计有效数值对数；双方未达到 95% 时不计算时间差，不填 0 或 1800。双方都确认过聚集才计算首次确认时间差。
- 无有效配对时不判断策略优劣。生成和验证使用同一批种子，只作描述性验证，不提供显著性结论或泛化改善承诺。行程完成不代表到达安全区。
- 原有局部动作效果评价仍按系统记录保留，第 2 类效果页面使用完整轮次的同种子对照，不把局部评价当作最终策略改善。
